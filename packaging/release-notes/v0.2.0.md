A job can now live as long as its client: `GET /v1/stdio` runs one over a WebSocket, a line each way, so an MCP server can run in its owner's sandbox instead of next to the application that calls it.

What is new:

- `/v1/stdio`, behind the same token, with the same owner, backend floor and network checks as `/v1/run`. No wall clock: closing either side ends the other. stderr is never relayed.
- `env` on a stdio job, for a token the server needs. The values go to the container through an owner-only `--env-file` removed with the job, never a command line or the container CLI's own environment.

```bash
curl -fsSL https://github.com/fajarhide/cordon/releases/latest/download/cordon-$(uname -m)-unknown-linux-musl.tar.gz | tar xz
sudo install cordon-$(uname -m)-unknown-linux-musl/cordon /usr/local/bin/
```

Unchanged limits: the host kernel is shared, and `open` is the host's full outbound access, unfiltered.
